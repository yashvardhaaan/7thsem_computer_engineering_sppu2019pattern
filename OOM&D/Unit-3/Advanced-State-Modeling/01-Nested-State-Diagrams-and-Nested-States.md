Topic 4 – State Models and Nested / Composite States

SPPU Exam-Oriented Notes
 High PYQ Priority

State models are used in UML to represent the different states of an object during its lifetime and how the object changes its state in response to events.

This topic is important because SPPU questions can ask both theoretical concepts and state diagrams.

The following answers are structured for university examinations, including definitions, UML notations, diagrams, examples and differences.

Q1. What is a State Model? Explain Events, States, Transitions and Guard Conditions.
Answer:
1. Definition of State Model
A state model is a UML behavioral model that describes the different states of an object and the transitions between those states in response to events.

It represents the dynamic behavior of an object throughout its lifetime.

A state model is generally represented using a State Machine Diagram (State Diagram).
2. Purpose of State Model
1. To represent the lifecycle of an object.
2. To show how an object changes its state.
3. To identify events that trigger state changes.
4. To model the behavior of reactive systems.
5. To represent conditional transitions.
6. To understand the behavior of complex systems.
3. Components of State Model
A. State

A state represents a condition or situation of an object during which it satisfies certain conditions or performs particular activities.
- Represented by a rectangle with rounded corners.
- An object remains in a state until an event causes a transition.
Example: An ATM machine can have the following states:
- Idle
- Card Inserted
- PIN Verification
- Transaction Processing
- Cash Dispensing
State notation
B. Event

An event is an occurrence or action that triggers a change in the state of an object.

Events may be generated by users, other objects or the system itself.

Examples:
- Card inserted
- PIN entered
- Button pressed
- Payment received
- Timeout occurred
C. Transition

A transition represents the movement of an object from one state to another when a particular event occurs.
- Represented by a directed arrow.
- It connects two states.
- It may contain an event, guard condition and action.
Example: When a customer inserts an ATM card, the ATM changes from Idle to Card Inserted.
Transition notation
D. Guard Condition

A guard condition is a Boolean expression that must be true for a transition to occur.
- Written inside square brackets [ ].
- It controls whether a transition can be executed.
- If the condition is false, that transition cannot occur.
Example:

During ATM PIN verification:
- [PIN valid] → Continue transaction.
- [PIN invalid] → Display error message.
E. Initial State
- Represents the starting point of a state machine.
- Represented by a filled black circle.
F. Final State
- Represents the termination of the state machine.
- Represented by a filled black circle surrounded by an outer circle.

Conclusion
A state model represents the lifecycle and behavior of an object using states, events, transitions and guard conditions.

Q2. What are Composite States? Explain their Categories.
Answer:
1. Definition
A composite state is a state that contains one or more substates inside it.

It is used to represent complex behavior by dividing a large state into smaller and manageable substates.

Composite states help simplify state diagrams and improve their readability.

For example, an ATM may have a composite state called Transaction Processing, which contains the substates:
- Cash Withdrawal
- Balance Enquiry
- Cash Deposit
Composite state containing substates
2. Categories of Composite States
Composite states are mainly classified into the following types:

A. Sequential Composite State (Non-orthogonal State)

A sequential composite state contains multiple substates that are executed one after another.
- Only one substate is active at a time.
- It represents alternative or sequential stages of a process.
- Transitions determine movement between substates.
Example: Online Order Processing

An order can have the following substates:
1. Order Placed
2. Payment Processing
3. Order Confirmed
4. Order Shipped
5. Order Delivered
Sequential composite state
Substates in sequential execution (illustrative)
B. Concurrent Composite State (Orthogonal State)

A concurrent composite state contains two or more regions that execute simultaneously.
- Multiple regions can be active at the same time.
- Each region has its own substates.
- Execution proceeds concurrently.
- Synchronization may be required before leaving the composite state.
Example: Online Shopping

After placing an order:
- Region 1: Payment Processing.
- Region 2: Inventory Processing.
Both activities can execute concurrently.
Concurrent composite state
Orthogonal regions executing simultaneously
3. Advantages of Composite States
1. Reduces the complexity of state diagrams.
2. Organizes related substates.
3. Supports hierarchical modeling.
4. Helps represent concurrent behavior.
5. Improves readability and maintenance.
Difference Between Sequential and Concurrent Composite States
Sequential Composite State	Concurrent Composite State
Contains sequential or alternative substates.	Contains multiple orthogonal regions.
Only one substate is active at a time within a region.	Multiple regions are active simultaneously.
Represents sequential behavior.	Represents parallel behavior.
Also called non-orthogonal state.	Also called orthogonal state.
Example: Order processing stages.	Example: Payment and inventory processing.

Conclusion
Composite states are used to represent complex states using smaller substates. They are mainly classified into sequential and concurrent composite states.

Q3. Draw a State Diagram for a Cash Dispenser and Explain Concurrency.
Answer:
1. Introduction
A cash dispenser is an electronic machine used to dispense cash when a valid withdrawal request is received.

A state diagram represents the different states of a cash dispenser and the transitions that occur when events take place.
2. States of Cash Dispenser
1. Idle – Waiting for a withdrawal request.
2. Amount Entered – Customer enters the withdrawal amount.
3. Validating – System validates the request.
4. Checking Cash – Checks whether sufficient cash is available.
5. Dispensing – Cash is dispensed.
6. Completed – Transaction is completed.
7. Error – An error occurs during processing.

In an ATM system, some operations can occur concurrently.

Example:

During a cash withdrawal:
- Region 1: Cash dispenser prepares and dispenses cash.
- Region 2: Bank system updates the account transaction record.
Both operations can execute concurrently.

Q4. Draw a State Diagram for a Telephone-Line Connection.
Answer:
1. Introduction
A telephone system establishes communication between two users through a telephone network.

A state diagram represents the different states of a telephone line during call establishment, communication and termination.
2. States of Telephone-Line Connection
1. Idle – Telephone is waiting for a call.
2. Off-Hook – User lifts the telephone receiver.
3. Dial Tone – Dial tone is generated.
4. Dialing – User enters the telephone number.
5. Connecting – System attempts to establish a connection.
6. Ringing – Receiver's telephone rings.
7. Connected – Communication is established.
8. Busy – Receiver is already engaged.
9. Disconnected – Call is terminated.

Q5. Explain the Relationship Between Class Model and State Model.
Answer:
1. Introduction
A class model and a state model are two important UML models used in object-oriented system development.
- A class model represents the static structure of a system.
- A state model represents the dynamic behavior of an object.
Both models complement each other and provide a complete understanding of the system.
2. Class Model
A class model describes the static structure of a system.

It represents:
1. Classes.
2. Attributes.
3. Operations or methods.
4. Relationships between classes.
5. Inheritance and associations.
Example: ATM System

A class called ATM may contain:
- Attributes: atmId, location, cashAvailable.
- Methods: validateCard(), verifyPIN(), dispenseCash().
UML class diagram representation
3. State Model
A state model describes how an object changes its state during its lifetime.

It represents:
1. States.
2. Events.
3. Transitions.
4. Guard conditions.
5. Actions.
Example: ATM System

The ATM object may have the following states:
- Idle
- Card Inserted
- PIN Verification
- Transaction Processing
- Cash Dispensing
4. Relationship Between Class Model and State Model
1. A class model defines the classes whose objects may have state-dependent behavior.
2. A state model describes the lifecycle of an object belonging to a particular class.
3. Events cause objects to change from one state to another.
4. Operations defined in a class can be executed during state transitions.
5. Attributes of a class can influence state transitions through guard conditions.
6. Both models are used together to understand the complete system.
5. Example
Consider an ATM class.

Class Model:
- Class: ATM
- Attributes: atmId, cashAvailable.
- Operations: verifyPIN(), dispenseCash().
State Model:
- Idle
- Card Inserted
- PIN Verified
- Processing
- Dispensing Cash
When the verifyPIN() operation is successful, the ATM object changes from PIN Verification to Transaction Processing.

6. Difference Between Class Model and State Model
Class Model	State Model
Represents static structure.	Represents dynamic behavior.
Describes classes and objects.	Describes states of objects.
Contains attributes and operations.	Contains states, events and transitions.
Shows relationships between classes.	Shows transitions between states.
Generally represented using a class diagram.	Generally represented using a state machine diagram.
Example: ATM class.	Example: ATM changing from Idle to Processing.

Conclusion
The class model describes what an object contains and what operations it performs, whereas the state model describes how the object behaves and changes its state during execution.
