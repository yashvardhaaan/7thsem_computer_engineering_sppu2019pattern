# 11. EVENTS

# 1. Definition of Event

An **event** is an occurrence or happening that causes a change in the state of an object.

In a UML **state diagram/state machine**, an event triggers a transition from one state to another.

### Exam Definition

> **An event is an occurrence that triggers a state transition in an object. It may be caused by an external action, a change in condition, or the passage of time.**

### Basic Representation

```text id="r8b7l4"
             Event
               |
               ↓
        +--------------+
        |    State A   |
        +--------------+
               |
             event
               |
               ↓
        +--------------+
        |    State B   |
        +--------------+
```

For example:

```text id="8w4c7q"
ATM Card Inserted
       ↓
Card Inserted State
       ↓
Authentication State
```

The event **"card inserted"** causes the transition.

---

# 2. Role of Events in State Modeling

A state describes **what an object is doing or its current condition**.

An event describes **something that happens and causes the object to change state**.

### Example

```text id="n1q5cv"
             pressButton
                ↓
+---------+             +----------+
|   OFF   |------------>|    ON    |
+---------+             +----------+
```

Here:

* `OFF` → State
* `ON` → State
* `pressButton` → Event
* Arrow → Transition

### Remember

> **State = condition of object**
> **Event = occurrence that causes change**

---

# 3. Components Related to an Event

In a state diagram:

```text id="h4k1y7"
 State A ---- event / action ----> State B
```

There are three important elements:

### 1. Source State

The state from which the transition starts.

### 2. Event

The occurrence that triggers the transition.

### 3. Target State

The state reached after the transition.

Example:

```text id="w2q5o0"
+-------------+
|   Locked    |
+-------------+
       |
    password
    correct
       |
       ↓
+-------------+
|  Unlocked   |
+-------------+
```

---

# 4. Types of Events

The major types of events that are important for the exam are:

1. **Signal Event**
2. **Call Event**
3. **Time Event**
4. **Change Event**

These should be prepared carefully because they are directly related to the Sept 2023 PYQ.

---

# 5. Signal Event

## Definition

A **signal event** occurs when an object receives a signal or notification from another object or external source.

The sender does not necessarily wait for the receiver to complete the operation.

### Example

A fire alarm sends a signal to a security system.

```text id="v7q5n9"
+----------------+
| Fire Detector  |
+----------------+
        |
     Fire Signal
        |
        ↓
+----------------+
| Alarm System   |
+----------------+
```

The **fire signal** is a signal event.

---

## Real-World Examples

* Fire alarm signal
* SMS received
* Network notification
* Emergency alert
* Sensor signal

### Exam Point

> **Signal Event → Event generated by sending/receiving a signal.**

---

# 6. Call Event

## Definition

A **call event** occurs when an operation or method is invoked on an object.

It is associated with a request to execute an operation.

### Example

Consider a bank account:

```text id="t9i5k3"
Customer
    |
 withdraw()
    |
    ↓
+-----------+
|  Account  |
+-----------+
    |
    ↓
Processing
```

The invocation of `withdraw()` generates a call event.

---

## Another Example

```text id="a6c9n0"
Login Screen
     |
 login()
     |
     ↓
Authentication
```

The call to `login()` can cause a transition.

### Exam Point

> **Call Event → Occurs when an operation/method is called.**

---

# 7. Time Event

## Definition

A **time event** occurs because of the passage of time or when a specified time condition is reached.

It is used when a state transition must happen at a particular time or after a particular duration.

### Example 1 — Alarm

```text id="8d5r0v"
+-----------+
| Sleeping  |
+-----------+
      |
   6:00 AM
      |
      ↓
+-----------+
|   Awake   |
+-----------+
```

The event **6:00 AM** causes the transition.

---

### Example 2 — ATM Session

Suppose an ATM automatically logs out after 30 seconds of inactivity.

```text id="w7p3m2"
+----------------+
|  Transaction   |
|    Active      |
+----------------+
        |
    after 30 sec
        |
        ↓
+----------------+
|   Logged Out   |
+----------------+
```

`after 30 sec` is a time event.

### Exam Point

> **Time Event → Triggered by a specific time or passage of time.**

---

# 8. Change Event

## Definition

A **change event** occurs when a specified condition or value becomes true.

It is triggered by a change in the value of some condition.

### Example

Suppose a bank account becomes blocked when:

```text id="4f6h8k"
balance < 0
```

The transition can be:

```text id="8p3d4q"
+----------------+
| Active Account |
+----------------+
        |
   balance < 0
        |
        ↓
+----------------+
| Blocked Account|
+----------------+
```

The condition `balance < 0` becoming true generates a change event.

---

## Another Example

In a temperature control system:

```text id="3k7m2s"
Temperature Normal
       |
  temperature > 40°C
       |
       ↓
Cooling ON
```

When the temperature crosses 40°C, the change event occurs.

### Exam Point

> **Change Event → Triggered when a condition becomes true because of a change in value.**

---

# 9. Comparison of Event Types

| Event Type       | Meaning                    | Example              |
| ---------------- | -------------------------- | -------------------- |
| **Signal Event** | Signal/message is received | Fire alarm signal    |
| **Call Event**   | Operation is called        | `withdraw()`         |
| **Time Event**   | Time condition occurs      | `after 30 sec`       |
| **Change Event** | Condition becomes true     | `temperature > 40°C` |

### Easy Memory Trick

```text id="8l1h5a"
SIGNAL → Message
CALL   → Method
TIME   → Clock
CHANGE → Condition
```

---

# 10. Event vs State vs Transition

These three concepts are commonly confused.

| Concept        | Meaning                            |
| -------------- | ---------------------------------- |
| **State**      | Condition/situation of an object   |
| **Event**      | Something that happens             |
| **Transition** | Movement from one state to another |

### Example

```text id="6v3w2p"
                  pressButton
                      |
                      ↓
+-----------+                  +-----------+
|    OFF    |----------------->|    ON     |
+-----------+                  +-----------+
```

Here:

* `OFF` → State
* `pressButton` → Event
* Arrow → Transition
* `ON` → State

### Remember

> **Event causes Transition.**

---

# 11. Events and State Diagram

Events are written on transitions.

General form:

```text id="4m7z9q"
+----------+       event       +----------+
|  State A |------------------>|  State B |
+----------+                   +----------+
```

For example:

```text id="0v6q1n"
+-----------+      insertCard      +-------------+
|   Idle    |--------------------->| Card Inserted|
+-----------+                      +-------------+
```

Here `insertCard` is the event.

---

# 12. Event with Guard Condition

An event can be associated with a **guard condition**.

General notation:

```text id="x4r8v2"
event [guard] / action
```

Example:

```text id="q1m7x9"
insertCard [valid] / authenticate
```

Meaning:

> When the card is inserted, if the card is valid, the transition occurs and authentication is performed.

### Diagram

```text id="j5n8c2"
+-------+ 
| Idle  |
+-------+
    |
 insertCard
 [valid]
 /authenticate
    |
    ↓
+-------------+
| Authenticate|
+-------------+
```

---

# 13. Event with Action

An event may trigger an action during the transition.

Notation:

```text id="2b6w9f"
event / action
```

Example:

```text id="f7p4s1"
insertCard / readCard
```

Meaning:

> When the card is inserted, the system reads the card.

---

### Events

## Question

> **"Define event and explain in brief different types of events." — 5 Marks**

This is a **direct theory question** and should be prepared exactly.

---

# Exam-Oriented Answer

## Definition

> **An event is an occurrence that causes a change in the state of an object. In a UML state diagram, an event triggers a transition from one state to another.**

Example:

```text id="w5n2x8"
+---------+      pressButton      +---------+
|   OFF   |----------------------->|   ON    |
+---------+                         +---------+
```

Here, `pressButton` is the event.

---

## Types of Events

### 1. Signal Event

A signal event occurs when an object receives a signal from another object or external source.

**Example:** Fire alarm signal.

```text id="f7k2m5"
Fire Detector
      |
 Fire Signal
      ↓
Alarm System
```

---

### 2. Call Event

A call event occurs when an operation or method is invoked.

**Example:**

```text id="r6v8n1"
withdraw()
    ↓
Bank Account
```

The invocation of `withdraw()` is a call event.

---

### 3. Time Event

A time event occurs when a specified time or duration is reached.

**Example:**

```text id="3j5q8w"
Transaction Active
       |
   after 30 sec
       ↓
Logged Out
```

---

### 4. Change Event

A change event occurs when a specified condition becomes true due to a change in value.

**Example:**

```text id="9x4c7m"
Normal
  |
temperature > 40°C
  ↓
Cooling ON
```

---

# 5-Mark Answer

> **Event:** An event is an occurrence that causes a change in the state of an object. In a state diagram, an event triggers a transition from one state to another.
>
> ```text
> +---------+       pressButton       +---------+
> |   OFF   |------------------------>|   ON    |
> +---------+                          +---------+
> ```
>
> The major types of events are:
>
> **1. Signal Event:** Occurs when a signal is received from another object or external source. Example: fire alarm signal.
>
> **2. Call Event:** Occurs when an operation or method is invoked. Example: `withdraw()`.
>
> **3. Time Event:** Occurs when a specified time or duration is reached. Example: ATM logout after 30 seconds.
>
> **4. Change Event:** Occurs when a specified condition becomes true due to a change in value. Example: `temperature > 40°C` turns on cooling.
>
> Thus, events are important in state modeling because they trigger transitions between different states of an object.

# PYQ 2 — OCTOBER 2022

## Question

> **"Explain how you model different events in state diagram." — 5 Marks**

This question is slightly different.

The examiner wants you to explain **how events are represented and modeled in a state diagram**, rather than simply defining their types.

---

# Exam-Oriented Answer

Events are modeled on the **transitions** connecting states.

The basic representation is:

```text id="y8m3r6"
+----------+        Event        +----------+
| State A  |-------------------->| State B  |
+----------+                     +----------+
```

The event causes the object to move from State A to State B.

---

## 1. Signal Event

Represent the occurrence of a signal.

```text id="1w5j8n"
Idle
 |
 | fireSignal
 ↓
Alarm
```

---

## 2. Call Event

Represent the invocation of an operation.

```text id="4q9s2k"
Idle
 |
 | withdraw()
 ↓
Processing
```

---

## 3. Time Event

Represent a time-based condition.

```text id="6n2p7v"
Active
 |
 | after(30 sec)
 ↓
Timeout
```

---

## 4. Change Event

Represent a condition becoming true.

```text id="9c4m6x"
Normal
 |
 | [temperature > 40°C]
 ↓
Cooling
```

---

# Event with Guard and Action

Events can also be modeled together with guards and actions:

```text id="e8v3k1"
event [guard] / action
```

Example:

```text id="n4x7q2"
insertCard [valid] / readCard
```

Meaning:

* `insertCard` → Event
* `[valid]` → Guard condition
* `/readCard` → Action

# 16. Common Mistakes

### ❌ Mistake 1

Writing:

> "Event is a state."

Wrong.

### Correct:

> Event is an **occurrence that triggers a transition**.

---

### ❌ Mistake 2

Confusing event with transition.

### Correct:

```text id="4g7x2s"
Event
  ↓
Triggers
  ↓
Transition
  ↓
New State
```

---

### ❌ Mistake 3

Giving only definitions without diagrams.

For a **5-mark state-modeling question**, include at least **one state diagram**.

---

### ❌ Mistake 4

Writing only three types when the question asks for different types.

Prepare all four:

```text id="j4w8n6"
Signal
Call
Time
Change
```
