# **Unit V – Blockchain Ethereum Platform Using Solidity**

## **Topic 3: EVM (Ethereum Virtual Machine)**

### **1. What is EVM?**

**EVM (Ethereum Virtual Machine)** is the execution environment of Ethereum. It executes smart contracts and processes transactions according to the rules of the Ethereum network.

It acts as a virtual computer that runs the program code stored in smart contracts.

- EVM stands for Ethereum Virtual Machine.
- It executes smart contracts deployed on Ethereum.
- It processes contract instructions in the form of bytecode.
- It maintains the rules for updating Ethereum's blockchain state.
- It provides a standard execution environment across Ethereum nodes.

**In simple words:** EVM is the engine that executes smart contracts on the Ethereum blockchain.

### **2. Why is EVM required?**

Before EVM, understand the problem it solves.

A smart contract contains instructions that must be executed consistently by the Ethereum network. If different nodes execute the same contract differently, the blockchain could become inconsistent.

EVM provides a common execution environment so that participating nodes can independently execute transactions and verify the resulting state.

Its main purposes are:

1. **Smart contract execution:** Runs the code of smart contracts.
2. **Consistency:** Ensures the same execution rules are followed across nodes.
3. **Decentralization:** Allows execution without depending on one central server.
4. **Security:** Runs contract code in a controlled environment.
5. **State management:** Processes changes to account balances and contract storage.

### **3. How does EVM work?**

## **EVM execution flow**

**1. User sends transaction**

A user interacts with a smart contract.

**2. Transaction is broadcast**

The transaction reaches the Ethereum network.

**3. EVM executes bytecode**

Contract instructions are processed.

**4. Gas is consumed**

Execution uses computational resources.

**5. Blockchain state is updated**

The transaction result is recorded when included in a valid block.

**Important:** Ethereum nodes execute and verify transactions according to the EVM rules. EVM is not one central computer; it is the execution environment implemented by Ethereum clients.

### **4. Important components of EVM**

| Component       | Explanation                                                        |
| --------------- | ------------------------------------------------------------------ |
| Stack           | Temporary data structure used for calculations and operations.     |
| Memory          | Temporary storage used during contract execution.                  |
| Storage         | Persistent storage that maintains contract data on the blockchain. |
| Program Counter | Keeps track of the next instruction to execute.                    |
| Gas             | Measures the computational resources consumed during execution.    |
| Bytecode        | Machine-readable instructions executed by the EVM.                 |

### **5. Role of Gas in EVM**

Gas is the unit used to measure the computational work required to execute operations on Ethereum.

Every EVM operation consumes a certain amount of gas.

**Why is gas required?**

- Prevents unlimited execution of smart contracts.
- Helps allocate computational resources.
- Discourages spam and unnecessary operations.
- Makes users pay for the resources their transactions consume.

If a transaction runs out of gas, execution fails. Changes made by that transaction are reverted, although the gas already consumed is still charged.

### **6. Advantages of EVM**

1. **Decentralized execution:** Smart contracts execute across the Ethereum network.
2. **Security:** Provides a controlled environment for executing contract code.
3. **Deterministic execution:** The same valid input and blockchain state produce the same execution result.
4. **Transparency:** Contract interactions and state changes can be verified.
5. **Compatibility:** Developers can deploy smart contracts using Solidity, which compiles to EVM bytecode.
6. **Automation:** Executes contract logic without requiring a central intermediary.

### **7. Limitations of EVM**

1. Complex operations can consume high gas.
2. Smart contract bugs can cause financial losses.
3. EVM execution is subject to network capacity and transaction fees.
4. Developers need to consider security and gas optimization while writing contracts.
