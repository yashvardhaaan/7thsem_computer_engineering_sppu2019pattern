# 2. Maintaining Software Quality Assurance (SQA)

Repeated 4 Times

## Definition

Maintaining Software Quality Assurance (SQA) is the continuous process of monitoring, evaluating and improving software development activities to ensure that software products meet defined quality standards and customer requirements.

It ensures that quality is maintained throughout the Software Development Life Cycle (SDLC), including development, testing, deployment and maintenance.

## Methods to Maintain SQA

1\. Establish Quality Standards

- Define quality standards, policies and procedures.
- Follow recognised standards such as ISO 9001 and relevant software engineering standards.
- Ensure that all team members understand quality requirements.

2\. Prepare and Follow an SQA Plan

- Develop a proper Software Quality Assurance Plan.
- Define quality objectives, responsibilities and testing activities.
- Establish procedures for quality monitoring.

3\. Conduct Regular Reviews and Audits

- Perform code reviews, design reviews and document reviews.
- Conduct SQA audits to verify whether processes follow established standards.
- Identify non-compliance and take corrective actions.

4\. Perform Software Testing

- Conduct unit, integration, system and acceptance testing.
- Perform functional and non-functional testing.
- Identify and remove defects before software release.

5\. Monitor Quality Metrics

- Measure defect density, test coverage and failure rates.
- Analyse collected data to identify quality problems.
- Take corrective actions based on measurements.

6\. Provide Employee Training

- Train developers, testers and other employees in quality practices.
- Improve technical knowledge and awareness of standards.
- Encourage responsibility for software quality.

7\. Configuration and Change Management

- Maintain proper versions of source code and documents.
- Control changes in software requirements and design.
- Ensure modifications do not introduce new defects.

8\. Continuous Improvement

- Collect feedback from customers and users.
- Identify the root causes of recurring defects.
- Improve processes through regular monitoring and corrective actions.

## Advantages of Maintaining SQA

1. Improves software reliability.
2. Reduces defects and development costs.
3. Increases customer satisfaction.

5. Improves development and testing processes.
6. Supports continuous quality improvement.

Conclusion: Maintaining SQA is a continuous activity that involves quality standards, planning, testing, audits, metrics and process improvement to deliver reliable software.

# 3. Software Maintenance

PYQ – Nov 2023

## Definition

Software Maintenance is the process of modifying and updating software after its delivery to correct defects, improve performance, adapt to changing environments and enhance functionality.

It is performed after software deployment to ensure that the application continues to work correctly and meets changing user requirements.

## Types of Software Maintenance

1\. Corrective Maintenance

- Performed to correct errors and defects discovered after software delivery.
- Improves software reliability by fixing identified problems.

Example: Fixing a payment failure occurring in an e-commerce application.

2\. Adaptive Maintenance

- Performed to adapt software to changes in its operating environment.
- Includes changes in operating systems, hardware, databases and external services.

Example: Updating an application to support a new version of an operating system.

3\. Perfective Maintenance

- Performed to improve software performance, functionality and usability.
- Adds new features according to user requirements.

Example: Adding a wishlist feature to an existing shopping application.

4\. Preventive Maintenance

- Performed to reduce the possibility of future failures.
- Includes code restructuring, refactoring and improving documentation.

Example: Refactoring poorly structured code to make future modifications easier.

## Software Maintenance Process

1\. Change Request

2\. Impact Analysis

3\. Modification and Implementation

4\. Testing and Verification

5\. Deployment

6\. Maintenance Review

## Advantages of Software Maintenance

1. Corrects software defects.
2. Improves performance and reliability.
3. Supports changing user requirements.
4. Improves security.
5. Extends software life.
6. Prevents future problems.

## Conclusion

Software Maintenance is an essential post-delivery activity that keeps software functional, reliable and updated. Its four types are Corrective, Adaptive, Perfective and Preventive Maintenance.

Important distinction: Software Maintenance modifies the delivered software product. Maintaining SQA maintains the quality assurance processes and standards used by an organisation.

# 4. SQA Goals and Metrics

PYQ Repeated 2 Times

## Definition

SQA Goals are the objectives established to ensure that software development processes and software products meet defined quality requirements.

SQA Metrics are measurable indicators used to evaluate software quality, process effectiveness and the achievement of SQA goals.

In simple words:

- Goals explain what quality objectives we want to achieve.
- Metrics explain how we measure whether those objectives are achieved.

## A. Goals of SQA

1\. Defect Prevention

- Prevent defects during software development.
- Use reviews, standards and proper development practices.

2\. Defect Detection

- Identify defects as early as possible.
- Perform testing, inspections and reviews.

3\. Process Improvement

- Improve software development and testing processes.
- Reduce unnecessary activities and inefficiencies.

4\. Customer Satisfaction

- Ensure software meets customer expectations.
- Deliver reliable and user-friendly software.

5\. Compliance with Standards

- Ensure development activities follow defined quality standards.
- Maintain proper documentation and procedures.

6\. Cost and Time Reduction

- Reduce rework and maintenance costs.
- Identify defects early to avoid expensive corrections later.

7\. Software Reliability

- Ensure software performs consistently under expected conditions.
- Reduce failures and improve availability.

## B. SQA Metrics

| Metric                            | Meaning                                               | Purpose                                 |
| --------------------------------- | ----------------------------------------------------- | --------------------------------------- |
| Defect Density                    | Number of defects per unit of software size           | Measures defect concentration           |
| Test Coverage                     | Percentage of requirements or code covered by tests   | Measures testing completeness           |
| Defect Removal Efficiency (DRE)   | Percentage of defects removed before release          | Measures defect detection effectiveness |
| Test Pass Percentage              | Percentage of executed tests that pass                | Measures test execution results         |
| Mean Time Between Failures (MTBF) | Average operating time between failures               | Measures reliability                    |
| Customer Defect Rate              | Defects reported by customers after release           | Measures field quality                  |
| Rework Percentage                 | Proportion of effort spent correcting or redoing work | Measures process efficiency             |

## C. Important SQA Metrics with Formulas

1\. Defect Density

\\[ \text{Defect Density} = \frac{\text{Number of Defects}}{\text{Software Size}} \\]

Example: If a software application contains 20 defects in 10,000 lines of code:

\\[ = \frac{20}{10} = 2 \\]

Defect density = 2 defects per 1,000 LOC.

2\. Test Coverage

\\[ \text{Test Coverage} = \frac{\text{Requirements Tested}}{\text{Total Requirements}} \times 100 \\]

Example: If 80 out of 100 requirements are tested:

\\[ = \frac{80}{100}\times100 = 80\\% \\]

3\. Defect Removal Efficiency (DRE)

\\[ DRE = \frac{\text{Defects Removed Before Release}} {\text{Defects Removed Before Release}+\text{Defects Found After Release}} \times100 \\]

Example: 90 defects are removed before release and 10 are discovered after release.

\\[ DRE = \frac{90}{90+10}\times100=90\\% \\]

4\. Test Pass Percentage

\\[ \text{Pass Percentage} = \frac{\text{Passed Test Cases}}{\text{Executed Test Cases}} \times100 \\]

Example: If 95 out of 100 executed test cases pass, the pass percentage is 95%.

5\. Mean Time Between Failures (MTBF)

\\[ MTBF = \frac{\text{Total Operating Time}}{\text{Number of Failures}} \\]

Example: If a system operates for 1,000 hours and experiences 5 failures:

\\[ MTBF = \frac{1000}{5}=200 \text{ hours} \\]

## D. Relationship Between SQA Goals and Metrics

| SQA Goal                          | Suitable Metric      |
| --------------------------------- | -------------------- |
| Reduce defects                    | Defect Density       |
| Improve testing                   | Test Coverage        |
| Improve defect detection          | DRE                  |
| Improve test execution            | Test Pass Percentage |
| Improve reliability               | MTBF                 |
| Improve released software quality | Customer Defect Rate |

## Conclusion

SQA goals define the quality objectives of software development, while SQA metrics measure the achievement of those objectives. Metrics such as defect density, test coverage, DRE and MTBF help organisations evaluate and improve software quality.

# 5. Software Quality Assurance Plan (SQA Plan)

PYQ – May 2024

## Definition

An SQA Plan is a formal document that describes the quality standards, procedures, responsibilities and activities that will be followed throughout a software project to ensure that the developed software meets specified quality requirements.

It acts as a guideline for developers, testers, project managers and quality assurance teams.

## Objectives of an SQA Plan

1. Define software quality objectives.
2. Establish quality standards and procedures.
3. Define roles and responsibilities.
4. Plan testing and review activities.
5. Identify quality risks.
6. Ensure compliance with standards.
7. Monitor and improve software quality.

## Components of an SQA Plan

1\. Purpose and Scope

- Defines the purpose of the SQA Plan.
- Specifies the software project and activities covered.

2\. Quality Objectives

- Defines expected software quality levels.
- Includes reliability, usability, security and performance requirements.

3\. Standards and Procedures

- Specifies applicable quality standards and development procedures.
- Defines coding, documentation and testing guidelines.

4\. Roles and Responsibilities

\- Defines responsibilities of developers, testers, project managers and SQA teams.

5\. Reviews and Audits

- Specifies code reviews, design reviews and quality audits.
- Ensures compliance with defined procedures.

6\. Testing Activities

- Defines testing levels and testing strategies.
- Includes unit, integration, system and acceptance testing.

7\. Defect Management

\- Defines procedures for identifying, reporting, tracking and resolving defects.

8\. Configuration Management

- Defines how source code, test cases and documents will be controlled.
- Ensures proper version management.

9\. Quality Metrics and Reporting

- Defines metrics used to measure software quality.
- Specifies reporting and monitoring procedures.

10\. Risk Management

- Identifies possible quality risks.
- Defines preventive and corrective actions.

## Advantages of an SQA Plan

1. Provides a systematic approach to quality management.
2. Defines clear responsibilities.
3. Reduces software defects.
4. Improves coordination between teams.
5. Ensures compliance with quality standards.
6. Helps monitor project quality.
7. Reduces project risks and rework.

## Conclusion

An SQA Plan is an important project document that defines quality objectives, standards, responsibilities, testing activities and quality monitoring procedures. It ensures that quality assurance activities are properly planned and implemented throughout the software development lifecycle.
