## Q1. What is Automation Testing in Software Testing? Explain briefly. (May 2023 – 6 Marks)

Definition:

Automation Testing is a software testing technique in which specialised tools, scripts and software are used to execute test cases automatically, compare actual results with expected results and generate test reports.

It reduces manual effort and improves the speed, accuracy and efficiency of software testing.

Objectives of Automation Testing:

1. To reduce repetitive manual testing.
2. To improve testing speed and efficiency.
3. To increase test accuracy.
4. To perform repeated testing consistently.
5. To improve test coverage.
6. To reduce long-term testing costs.

Process of Automation Testing:

1. Test Case Selection: Identify test cases suitable for automation.
2. Tool Selection: Select appropriate automation tools.
3. Test Script Development: Write scripts to execute test cases.
4. Test Execution: Execute automated scripts.
5. Result Comparison: Compare actual results with expected results.
6. Test Reporting: Generate reports containing passed and failed test cases.

Example:

Consider an online shopping application.

A tester creates an automated script using Selenium WebDriver to:

- Open the website.
- Enter username and password.
- Click the Login button.
- Verify whether the user successfully logs in.
- Generate a test execution report.

The same test can be executed repeatedly without manually performing each step.

Popular Automation Testing Tools:

- Selenium WebDriver
- Cypress
- Playwright
- Appium
- JUnit
- TestNG

Conclusion: Automation Testing uses tools and scripts to execute software tests automatically, improving testing efficiency, accuracy and reliability.

## Q2. Identify / List and Explain Benefits of Automation Testing. (Nov 2022, May 2023, May 2024 – 6 Marks)

Repeated 3 Times

Definition:

Automation Testing provides several benefits by reducing manual testing effort and improving the speed, accuracy and reliability of software testing.

### Benefits of Automation Testing

1\. Faster Test Execution

Automated test scripts execute test cases faster than manual testing, saving time.

2\. Increased Accuracy

Automation reduces human errors and ensures consistent execution of test cases.

3\. Reusability of Test Scripts

Once created, automated scripts can be reused for different testing cycles.

4\. Improved Test Coverage

Automation allows testers to execute a large number of test cases and scenarios.

5\. Cost Effectiveness

Although initial setup costs are high, automation reduces repetitive testing costs over time.

6\. Supports Regression Testing

Automated scripts can repeatedly verify existing functionalities after software modifications.

7\. Continuous Testing

Automation supports frequent test execution during development and CI/CD processes.

8\. Detailed Test Reports

Automation tools generate reports containing execution status, failures, errors and other testing information.

9\. Parallel Execution

Automated tests can run simultaneously across multiple browsers, devices or environments when supported by the tools and infrastructure.

10\. Increased Productivity

Testers spend less time on repetitive activities and more time identifying complex defects.

Example:

Consider an e-commerce application where 500 test cases need to be executed after every software update.

Using automation tools such as Selenium and TestNG, testers can execute these test cases automatically and generate reports without manually repeating every test.

Conclusion: Automation Testing improves testing speed, accuracy, coverage and productivity while reducing repetitive manual effort and long-term testing costs.

## Q3. Differentiate between Manual Testing and Automation Testing. (May 2024 – 6 Marks)

Definition:

- Manual Testing: Testing performed manually by a tester without using automation scripts to execute the test steps.
- Automation Testing: Testing performed using tools and scripts to execute test cases automatically.

### Difference between Manual Testing and Automation Testing

| Manual Testing                                                | Automation Testing                                              |
| ------------------------------------------------------------- | --------------------------------------------------------------- |
| 1. Test cases are executed manually by testers.               | 1. Test cases are executed using automation scripts.            |
| 2. Requires more human effort.                                | 2. Reduces repetitive human effort.                             |
| 3. Generally slower for repetitive testing.                   | 3. Faster for repetitive and large-scale testing.               |
| 4. More prone to human errors.                                | 4. Provides consistent execution when scripts are reliable.     |
| 5. Requires less initial investment in tools.                 | 5. Requires initial investment in tools and script development. |
| 6. Suitable for exploratory testing.                          | 6. Suitable for repetitive and regression testing.              |
| 7. Test execution is difficult to repeat at large scale.      | 7. Test scripts can be reused multiple times.                   |
| 8. Test reporting may require manual preparation.             | 8. Reports can be generated automatically.                      |
| 9. Less suitable for frequent large-scale regression testing. | 9. Highly suitable for frequent regression testing.             |
| 10. Example: Manually testing a login page.                   | 10. Example: Testing login using Selenium scripts.              |

Conclusion: Manual Testing is performed by human testers, whereas Automation Testing uses tools and scripts to execute tests faster and more consistently.
