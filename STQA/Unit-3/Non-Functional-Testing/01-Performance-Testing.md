## Q1. Explain Non-Functional Testing and Performance Testing with an example. (May 2023 – 6 Marks)

### 1. Non-Functional Testing

Definition:

Non-Functional Testing is a type of software testing that checks the non-functional aspects of an application, such as performance, security, reliability, usability and compatibility.

It verifies how well the software works rather than what functionality it performs.

Objectives:

1. To check software performance and response time.
2. To ensure application security.
3. To verify compatibility with different devices and platforms.
4. To check reliability and stability.
5. To improve user experience.

Types of Non-Functional Testing:

1. Performance Testing
2. Load Testing
3. Stress Testing
4. Security Testing
5. Compatibility Testing
6. Usability Testing
7. Reliability Testing
8. Scalability Testing
9. Recovery Testing

Example:

Consider an online banking application.

Non-Functional Testing verifies:

- Whether the application responds quickly.
- Whether it supports thousands of simultaneous users.
- Whether customer information is secure.
- Whether it works on different browsers and devices.

Conclusion: Non-Functional Testing ensures that software meets quality requirements such as speed, security, reliability and usability.

### 2. Performance Testing

Definition:

Performance Testing is a type of Non-Functional Testing used to evaluate the speed, responsiveness, stability and scalability of a software application under different workloads.

It helps determine how efficiently an application performs when users access it.

Objectives:

1. To measure application response time.
2. To determine system throughput.
3. To identify performance bottlenecks.
4. To check system stability under different workloads.
5. To evaluate resource utilisation such as CPU and memory.

Types of Performance Testing:

1\. Load Testing: Checks application performance under expected or normal user loads.

2\. Stress Testing: Checks application behaviour beyond its normal operating capacity to identify its breaking point and recovery behaviour.

3\. Spike Testing: Checks system performance when the workload suddenly increases or decreases.

4\. Endurance Testing: Checks application stability when it operates under a sustained workload for a long period.

5\. Volume Testing: Checks application performance when handling a large volume of data.

6\. Scalability Testing: Checks whether the application can handle increasing workloads by adding resources.

Example:

Consider an online shopping website during a festival sale.

- 1,000 users access the website simultaneously.
- Testers measure page response time.
- They check whether products load correctly.
- They monitor CPU and memory usage.
- They gradually increase the number of users to identify performance limitations.

If the website responds slowly or crashes, performance bottlenecks are identified.

Advantages:

1. Improves application speed and responsiveness.
2. Identifies performance bottlenecks.
3. Ensures system stability.
4. Improves user satisfaction.

Conclusion: Performance Testing ensures that an application performs efficiently under different workloads without compromising speed and stability.

## Q2. Explain any Two Types of Non-Functional Testing. (Nov 2024 – 6 Marks)

You can write any two of the following types. Prepare Security Testing and Compatibility Testing particularly well because they also appear in May 2025.

### 1. Security Testing

Definition:

Security Testing is a type of Non-Functional Testing used to identify vulnerabilities and verify that software protects data and resources against unauthorised access, attacks and misuse.

Objectives:

1. To protect confidential information.
2. To prevent unauthorised access.
3. To identify security vulnerabilities.
4. To verify authentication and authorisation.
5. To protect data from modification or theft.

Example:

Consider an online banking application.

- Enter an incorrect password multiple times.
- Try accessing another user's account.
- Check whether sensitive information is encrypted.
- Verify that unauthorised users cannot perform transactions.

Conclusion: Security Testing ensures that software and user data are protected against security threats.

### 2. Compatibility Testing

Definition:

Compatibility Testing is a type of Non-Functional Testing used to verify whether an application works correctly across different operating systems, browsers, devices, networks and hardware configurations.

Types:

1. Browser Compatibility: Checks application behaviour on Chrome, Firefox, Edge and Safari.
2. Operating System Compatibility: Checks application behaviour on Windows, Linux, Android and iOS.
3. Device Compatibility: Checks application behaviour on mobiles, tablets and desktops.
4. Network Compatibility: Checks application behaviour under different network conditions.

Example:

Consider an online shopping website.

Testers verify whether the website works correctly on:

- Google Chrome and Mozilla Firefox.
- Windows and macOS.
- Android and iOS.
- Desktop, tablet and mobile devices.

Advantages:

1. Ensures consistent application behaviour.
2. Improves user experience.
3. Identifies device and browser-specific defects.
4. Increases software reliability.

Conclusion: Compatibility Testing ensures that software works correctly across different platforms and environments.

### 3. Usability Testing

Definition:

Usability Testing verifies whether an application is easy to learn, understand and use by end users.

Example: Testing whether users can easily register, log in and complete a purchase on an online shopping website.

### 4. Reliability Testing

Definition:

Reliability Testing checks whether software performs consistently without failure for a specified period under given conditions.

Example: Checking whether a banking application operates continuously for several days without unexpected failures.

## Q4. Explain Performance Testing and Security Testing. (May 2025 – 6 Marks)

This question combines two Non-Functional Testing techniques.

### 1. Performance Testing

Performance Testing evaluates the speed, responsiveness, stability and scalability of an application under different workloads.

Important points:

- Measures response time.
- Checks throughput.
- Identifies performance bottlenecks.
- Tests system stability under heavy workloads.

Example: Testing an e-commerce website with 5,000 simultaneous users to verify whether it responds quickly without crashing.

### 2. Security Testing

Security Testing verifies whether an application is protected against unauthorised access, data theft and security vulnerabilities.

Important points:

- Checks authentication and authorisation.
- Identifies security vulnerabilities.
- Verifies data encryption.
- Prevents unauthorised access.
- Checks protection against common attacks.

Example: Testing a banking application to verify whether an unauthorised user can access another customer's account or perform transactions.

Conclusion: Performance Testing checks how efficiently software works, whereas Security Testing checks how safely software protects its data and resources.

## Q5. Explain Compatibility Testing and Security Testing. (May 2025 – 6 Marks)

### 1. Compatibility Testing

Compatibility Testing verifies whether software works correctly across different hardware, software, operating systems, browsers and devices.

Objectives:

1. To ensure cross-platform functionality.
2. To identify browser-specific defects.
3. To verify operating system compatibility.
4. To ensure consistent user experience.

Types:

- Browser Compatibility Testing.
- Operating System Compatibility Testing.
- Device Compatibility Testing.
- Network Compatibility Testing.
- Hardware Compatibility Testing.

Example:

An online banking website is tested on Chrome, Firefox, Windows, Android and iOS to ensure that all features work correctly.

### 2. Security Testing

Security Testing verifies whether an application protects its data and resources from unauthorised access and cyberattacks.

Objectives:

1. To identify security vulnerabilities.
2. To protect confidential information.
3. To verify authentication and authorisation.
4. To prevent unauthorised access.
5. To ensure data integrity and confidentiality.

Example:

A banking application is tested by entering incorrect passwords, attempting unauthorised account access and checking whether sensitive information is protected.

Conclusion: Compatibility Testing ensures software works across different environments, whereas Security Testing ensures software is protected against security threats.
